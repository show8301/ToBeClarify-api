# 餐飲折抵與品項營收認列

計算公式版本 5 將餐飲折抵限制在一般 `menu_item`／`menu_set`，排除香檳塔。指名費、指名服務、加購、包廂及小費不分攤餐飲折抵。

1. 品項先扣已取消金額；指名項目的子服務沿用父履約單元的取消比例。
2. 一般餐飲優先沿用履約單元保存的 `ORIGINAL_CREDIT - RETURNED_CREDIT`。舊資料無快照時，依有效餐飲金額分攤剩餘折抵，累計整數分配保留最後一 Gil。
3. 品項折抵後金額，再乘「調整後非小費應收／原非小費應收」及「有效淨實收／調整後整單應收」。有效淨實收沿用逐單對帳、待確認及保留款排除、超收上限。
4. 小費維持自己的有效實收認列，再依既有指定／公共小費規則分配。

取消或退回折抵與訂單折抵總額不一致時，列出 `MEAL_CREDIT_RECONCILIATION_REQUIRED` 與可開啟的訂單；不允許正式結算／確認新版。餐飲收入、指名分成、公司營收、服務員／經理池、幕後池與活動日收入均共用此結果。

## 金額來源與歷史

新來源快照保存原始品項金額、取消金額、餐飲折抵、折抵後金額、原／調整後非小費應收，以及原有整單應收／有效實收。Web 依快照顯示每一步與分成比例。支援服務分潤與主要指名職位沿用相同逐項來源，不複製小費。

既有版本保持原始金額及空白新欄位，不能以現況推補歷史。經理預覽、填原因確認後才產生第 5 版計算結果；版本差異、支付與追回依既有重新結算流程保留。

## 發布與驗證

先依專案既有本機 DBA 流程套用 [20261021_02_settlement_meal_credit_sources.sql](../db/migrations/20261021_02_settlement_meal_credit_sources.sql)，再發布 API，最後發布 Web dev。此 migration 僅增加五個可空白欄位，不更新舊來源或重算業務資料。API 只有正式主機；Web 正式版另依 dev 驗收流程推進。

記憶體驗證包含 150,000 指名＋10,000 餐飲全額折抵、部分實收、退款、保留、訂單調整、多筆餐飲、取消與折抵退回、香檳塔、混合小費、活動日與舊非帳本訂單。另執行薪資、香檳塔與重新結算既有檢查；儲存測試以獨立 loopback 資料庫驗證來源快照與 migration 可重跑。
