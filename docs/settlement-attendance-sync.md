# 出勤與結算同步

未正式結算的預覽會依已保存出勤與已核准、出勤中的班表，補入缺少的計薪輸入。

- 有效工時大於零時，依核准班表分別補入缺少的前台計薪角色及幕後參與角色。幕後可以兼任指名人員、服務生或經理。
- 前台角色只有一個（指名／服務生／經理）時自動帶入工時；只有幕後角色的既有輸入不會阻擋補入前台角色。
- 尚無前台輸入且核准班表包含多個前台角色，或完全無法辨識角色時，回傳 `ATTENDANCE_ROLE_UNRESOLVED`，由管理者確認工時分配；幕後角色不計入這項歧義。
- 既有結算角色、幕後參與、活動時數、備註與公共小費設定保留；實際分鐘以出勤的共同計算邏輯更新。
- 人工區間優先於打卡與班表區間；重疊區間合併後計時，再加減修正分鐘，最低為零。未結束的上班紀錄不推算尚未完成的工時。
- 核准角色包含幕後技術且有有效出勤時，新增幕後輸入預設參與分配；既有人工取消參與的設定不會被改回。非活動日幕後按人數分潤，不重複支付前台時薪或公共小費；活動日仍需明確確認分配時數。
- 讀取／重新檢核只產生預覽，不新增資料庫輸入。保存輸入或重新計算時才儲存；正式結算前也會重新計算並儲存。
- 自動輸入、既有人員的有效分鐘及薪資結果在同一交易保存，鎖定結算列後再次確認未正式結算。若其他操作已新增同一角色或衝突的前台角色，回傳 `SETTLEMENT_INPUTS_CHANGED`，要求重算；同一人合法的前台／幕後兼任不視為衝突。
- 已正式結算時不補入自動角色，薪資沿用鎖定結果。
- 沒有指名營業額的指名角色仍計入工時底薪；缺少指名輸入的薪資列標記為待處理，保留分潤／小費預覽。

例如：三月五日核准角色為 `designated`，班表 120 分鐘，人工修正後有效出勤 60 分鐘；重新檢核會帶入指名人員 60 分鐘，重新計算後保存，不需重複補登出勤或手動新增相同角色。

手動或明確要求時可執行回歸檢查（不加入 dev 發布流程）：

```powershell
dotnet run --project tests/AttendanceSettlementSync/AttendanceSettlementSync.csproj
```
